# Solicitação de Implementação: Isolamento de Banco de Dados para Testes E2E

## Contexto Técnico
- **Stack:** Node.js, Fastify, Prisma ORM, Vitest.
- **Status Atual:** Os testes E2E já estão criados e validados logicamente. O ambiente de desenvolvimento utiliza Docker Compose.
- **Problema:** Tentativas anteriores com `test-environment` do Vitest falharam devido a limitações no adapter do Prisma. Preciso de uma estratégia de isolamento que não utilize proxies complexos ou "gambiarras" manuais.

## Objetivo
Configurar um ambiente de banco de dados isolado para testes E2E que seja profissional, escalável para CI/CD e siga as melhores práticas de ambientes (Dev, Test, Prod).

## Requisitos e Restrições
1. **Isolamento Real:** Cada execução de teste deve operar em um banco (ou schema) limpo para evitar efeitos colaterais entre suítes.
2. **Automação do Ciclo de Vida:** O processo deve criar o banco/schema, rodar as migrations (`prisma migrate deploy`) e realizar o teardown automaticamente.
3. **Sem Proxies:** Evitar soluções de proxy de banco de dados; focar em manipulação de `DATABASE_URL` ou containers efêmeros.
4. **Integração com Vitest:** A solução deve se integrar ao fluxo de execução do Vitest (via Global Setup ou Custom Environment).

## Entregáveis Esperados
1. **Estratégia de Ambiente:** Sugestão de como gerenciar a `DATABASE_URL` dinamicamente para o ambiente de testes.
2. **Configuração do Docker:** Ajustes necessários no `docker-compose.yml` ou scripts de suporte para subir o banco de testes de forma independente.
3. **Script de Setup/Teardown:** Exemplo prático de um script que prepare o banco (migrations + seed se necessário) antes dos testes e limpe após a conclusão.
4. **Configuração do Vitest:** Como mapear o `vitest.config.ts` para reconhecer e injetar essas configurações sem conflitar com o Prisma Client.
